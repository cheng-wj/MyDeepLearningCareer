## 一、为什么重排（先看这段，免得又停摆）

| 事实 | 教训 |
|---|---|
| 国庆假期表按「每天下午 4h」排，实际只完成 Day 1 | **假期作息套不上工作日作息**，整块时间在上班后不存在 |
| 场次制（10-13 建）按「周中晚 3h + 周末 3.5h」排，10-14 至今**一场没做** | 排期时没问「你下班后到底能坐多久」，档期是拍脑袋定的 |
| 本表档期**按用户 10-28 给的真实时间预算**排：工作日晚 2h × 每周 2 场，周末每晚 3.5h | 档期必须来自真实约束，不是来自理想作息 |

**因此本表有三条和旧表不同的硬规矩：**

1. **到点就收。** 工作日晚场 2h 封顶，周末场 3.5h 封顶。不许"今天状态好就多做一小时"，那是停摆的开始。
2. **每场都有 15 分钟保底版**（见下方「保底动作」）。做不动完整场就做保底版，**链条不断比做完更重要**。
3. **允许顺延，禁止回补。** 某场没做就顺延到下一个档期，不补、不合并、不硬撑。

## 三、每场怎么开场（照做，别自己发明流程）

**开场 15 分钟固定动作**（不是"热身"，是防止断链）：

1. 打开仓库根目录，`E:\conda\envs\torch\python.exe pytorch学习\<上一场产出>.py` —— **跑一遍上一场的脚本**，确认还能跑。
2. 跑不起来 → 先修它，这 15 分钟就算本场内容。**断链了必须先接上**。

**主体 90 分钟 / 165 分钟**：看视频 → 自己写 → 跑 → 修。
**收尾 15 分钟**：打印关键指标（loss / accuracy / 显存）→ 确认 `git status` 里只有该有的文件。

**保底动作（只够 15 分钟时做这个）**：

> 把上一场的脚本原样跑一遍，**改一个参数**（`batch_size` / `epochs` / `num_workers`），看输出怎么变。

做保底不算失败，**连续两天做保底 = 链条还活着**。这条是本表最重要的一条。

## 四、场次说明（每场的坑位提示）

- **S1**：P06 是概念集，**看视频不写代码**，15 分钟打住。P07 重点是 `__getitem__` / `__len__` 两个协议。P14 直接用 `torchvision.datasets.CIFAR10` 感受一下封装。
- **S2**：P08/P09 是纯工具（TensorBoard），**不影响后面任何一集**，时间紧就砍。P10–P13 不用逐个学——挑 `ToTensor` / `Resize` / `RandomCrop` / `Normalize` 写进 `p10_transforms.py`，其余用到再查。
- **S3**：P15 注意 **Windows 下 `num_workers>0` 会报错**，先写 `num_workers=0` 跑通再试。P16 重点是 `nn.Module` 的 `__init__` 里注册子模块、`forward` 里写前向。
- **S4**：P17 概念集快进。`p19` / `p20` / `p21` 都很小，时间紧就合并成一个 `p18_p21_cnn_parts.py`。**P22 是本场硬产出**，Sequential 那张 CIFAR10 小网络必须搭出来。
- **S5**：P23 重点 `loss.backward()` 之后 `.grad` 有值；P24 重点 `zero_grad()` 别忘（`set_to_none=True` 现在是默认值）。验收用"打印参数前后值"最直接。
- **S6**：**本表唯一的硬目标场**。P27–P29 是同一个脚本的三集，本场要的是**跑起来**，不要求跑满 epoch、不要求准确率。P26 顺手做了（存 checkpoint）。
- **S7**：`p30` 本质是把 `p27` 复制一份加 `.to(device)` 三件套（模型 / 输入 / 标签）+ `argparse`，**不涉及新概念**。GPU 万一不可用，退回 CPU 跑 `p27` 即可，不阻塞。
- **S8**：P32 验证套路 = 加载权重 → `model.eval()` → `with torch.no_grad()` → 累计正确数 / 总数。P25（改预训练 vgg16 最后一层）对 Halcon/CV 路线**不是必须**，时间紧砍掉。P33 去 GitHub 逛 torchvision / ultralytics 源码纯属兴趣，**可永远不做**。
